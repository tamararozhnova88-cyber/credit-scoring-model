# Credit Scoring MLOps — PD prediction

End-to-end educational MLOps project on the **UCI Default of Credit Card Clients** dataset (30,000 observations). Target: `default.payment.next.month` (1 = next-month default). Intended for demonstration, **not for production credit decisions** without independent validation, fairness and compliance assessment.

## Architecture

`raw CSV → Pandera validation → stratified prepare (80/20) → sklearn feature engineering + imputation + scaling + one-hot → 5 MLflow CV experiments → GridSearchCV → holdout ROC-AUC/Precision/Recall/F1 + ROC → joblib/MLflow → FastAPI/Docker → PSI monitoring`

- `data/raw/` — source CSV (from supplied archive)
- `data/processed/` — deterministic split (generated by DVC)
- `src/data/` — preparation and data validation
- `src/features/` — engineered payment aggregates and age bins
- `src/models/` — pipeline, five experiments, CV search, metrics, inference
- `src/api/` — FastAPI `/predict`, `/health`
- `src/monitoring/` — sample requests and PSI
- `tests/` — unit and API tests, anomaly rejection
- `.github/workflows/` — GitHub Actions checks
- `dvc.yaml` — prepare and train stages
- `notebooks/` — EDA notebook

## Installation

Requires Python 3.11. Run commands from the repository root:

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m scripts.validate_data
pytest -q
```

## Reproducible pipeline and MLflow

```bash
dvc init
dvc add data/raw/UCI_Credit_Card.csv
# Commit .dvc/config, .dvcignore, data/raw/UCI_Credit_Card.csv.dvc and dvc.lock to Git.
dvc repro
mlflow ui --backend-store-uri ./mlruns --port 5000
```

**Note:** DVC initialization is a one-time local setup; `dvc.yaml` is already supplied. DVC remote storage is optional, configure separately for team collaboration. `dvc repro` may take several minutes because it fits five 3-fold CV models and a final grid search. `metrics.json`, `reports/figures/roc_curve.png`, and `models/credit_default_model.pkl` are produced by training. The holdout test set is used only once after model selection.

If DVC is not initialized, run directly:

```bash
python -m src.data.make_dataset data/raw/UCI_Credit_Card.csv data/processed
python -m src.models.train
```

## API

```bash
uvicorn src.api.app:app --host 127.0.0.1 --port 8000
# Open http://127.0.0.1:8000/docs
```

Send a JSON object with all 23 raw model input features (all columns except ID and target) to `POST /predict`. The response includes `default_prediction` (0 or 1) and `default_probability` (0–1). To create a valid sample request from the test data:

```bash
python -c "import pandas as pd,json; d=pd.read_csv('data/processed/test.csv'); print(json.dumps(d.drop(columns='default.payment.next.month').iloc[0].to_dict()))"
```

## Docker

Train locally **before** building the image; the Dockerfile copies the trained model.

```bash
bash scripts/docker_build_run.sh
# Windows: ./scripts/docker_build_run.ps1
```

Visit `http://localhost:8000/docs` to exercise `/predict`.

## Drift monitoring

With the API running:

```bash
python -m src.monitoring.drift --api-url http://localhost:8000 --sample-size 200
```

The script sends test records to `/predict`, compares score distributions against training scores using PSI with training-quantile bins, and saves `reports/drift.json`. PSI >= 0.2 triggers a warning (heuristic, not a regulatory standard). Test set serves as a *simulation* of incoming data, not real live drift.

## Tests and CI

`pytest -q`, `black --check src tests scripts`, `flake8 src tests scripts --max-line-length=100 --extend-ignore=E203,W503`. GitHub Actions runs these and Pandera validation on push/PR. A corrupted raw data file fails the validation step. The source dataset is included for local reproducibility; its original distribution is not assumed to represent today's applicants.

## Evaluation

Inspect `metrics.json`, the ROC curve, and the six MLflow runs (five initial experiments plus tuned final). ROC-AUC is the model selection criterion; Precision, Recall and F1 use a 0.5 threshold. No performance numbers are claimed until training runs successfully. For production, add threshold calibration, fairness audits, drift alerts, model registry governance, secrets management, monitoring, and a remote DVC backend.
